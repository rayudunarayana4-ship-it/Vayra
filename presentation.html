PROJECT VISION

Executive Summary: From Prototype to Production

1. Legacy Challenges
Client-Side Limitations
  • Volatile Storage: Products and orders stored in browser localStorage, lost upon clearing history.
  • Multi-Device Desync: Changes made in Admin never reached other customers' devices.
  • Coupling Hazard: Risk of accidental collision with TWO BROTHERS website and databases.
  • Hardcoded Mock Loops: Fallback logic automatically re-injected unwanted demo shoes.
2. Architectural Solution
Enterprise Separation
  • Dedicated Backend: Spring Boot 4 REST service running on custom port 8082.
  • Relational DB: Independent MySQL database (vayra_footwear_db) on port 3306.
  • Single Source of Truth: MySQL governs 100% of product inventory, slides, and orders.
  • Zero-Touch Isolation: Zero changes to Two Brothers store, backend (8081), or database.
3. Business Outcomes
Production Ready
  • Absolute Precision: Exactly what Admin configures appears on the storefront.
  • Live Fulfillment: Orders persistently recorded with customer phone, address, and line items.
  • Dynamic Content: Hero slides and promotions managed dynamically with zero code rebuilds.
  • Production Builds: Clean builds with 0 frontend lint errors and verified Maven JAR.
SYSTEM TOPOLOGY

3-Tier Enterprise Full-Stack Architecture

Tier 1: Client Front-End
Port 5173 • React 19 + Vite
  • Customer Storefront: Luxury monochrome theme, responsive grid, dynamic hero carousel.
  • Interactive Filtering: Category tabs (Sneakers, Loafers, Boots), price sorting, live search.
  • Cart & Checkout: Slide-out drawer with real-time subtotal and direct modal checkout.
  • Admin Command Hub: Real-time KPIs, multi-image uploader, order management.
  • API Client: Centralized Axios/Fetch layer with transparent offline caching.
Tier 2: Backend Microservice
Port 8082 • Spring Boot 4 / Java 17
  • REST API: Modular controllers for /api/products, /api/slides, /api/orders.
  • Spring Data JPA: Hibernate ORM with custom repository status filters.
  • Collection Synchronization: Map-based JSON updates preventing empty list overrides.
  • CORS Policy: Seamless pre-flight allowance for Vite frontend (5173).
  • Auto-DDL: Automated schema lifecycle management.
Tier 3: Relational Persistence
Port 3306 • MySQL 8
  • vayra_footwear_db: Dedicated schema isolated from all other databases.
  • Normalized Structure: Dedicated tables for products, images, sizes, specs, slides, orders.
  • Cascade Integrity: Deleting a footwear model automatically deletes child images.
  • Complete Isolation: 0 interaction with two_brothers_db on port 8081.
  • Index Optimization: Indexed by active and created_at.
RELATIONAL SCHEMA

Dedicated MySQL Database: vayra_footwear_db

Core Footwear Tables
products & child collections
  • products: id (PK), name, price, original_price, category, description, stock, active, featured, material, created_at, updated_at.
  • product_images: product_id (FK), images (URL) — Strict 1:1 row mapping.
  • product_sizes: product_id (FK), sizes (e.g. UK 7, UK 8, UK 9, UK 10).
  • product_details: product_id (FK), details (Handcrafted leather, Italian sole).
  • Cascade Delete: Deleting a product removes all linked image rows cleanly.
Banners & Fulfillment Tables
slides, orders & order_items
  • slides: id (PK), title, subtitle, image, tag, discount, cta_text, sort_order, active.
  • orders: id (PK), customer_name, customer_email, customer_phone, shipping_address, payment_method, total_amount, status.
  • order_items: id, order_id (FK), product_id, title, size, price, quantity.
  • Lifecycle: Admin can advance order statuses in real time.
DATA INTEGRITY

The Single Source of Truth Principle

Zero Means Zero
No Ghost Products
  • If Admin deletes all products, storefront renders exactly 0 shoes.
  • No mock products or demo fallback shoes will ever appear automatically.
Exact Counts
1-to-1 Accuracy
  • Add 1 shoe = Exactly 1 shoe shows up.
  • Add 5 shoes = Exactly 5 shoes show up.
  • Real-time synchronization across all devices.
Strict Images
Exact Row Count
  • 1 uploaded image = Exactly 1 row in product_images.
  • 3 images = Exactly 3 rows in database.
  • 0 images = Exactly 0 rows.
Status Control
Visibility Toggles
  • Toggle active = false instantly hides product from storefront.
  • Remains fully visible and editable inside Admin Dashboard.
BACKEND ARCHITECTURE

Spring Boot REST API Microservice (Port 8082)

Product & Inventory Endpoints
ProductController.java
  • GET /api/products — Admin view (all products).
  • GET /api/products?activeOnly=true — Customer storefront query.
  • GET /api/products/{id} — Single footwear item with images & sizes.
  • POST /api/products — Creates product with nested collections.
  • PUT /api/products/{id} — Atomic synchronization of fields & images.
  • PATCH /api/products/{id}/stock — Instant stock adjustment.
  • PATCH /api/products/{id}/status — Toggle active visibility.
  • DELETE /api/products/{id} — Permanent cascade deletion.
Slides & Orders Endpoints
SlideController & OrderController
  • GET /api/slides — Retrieves promotional hero banners.
  • POST /api/slides — Adds new promotional slide.
  • PUT /api/slides/{id} — Updates banner images & CTA links.
  • DELETE /api/slides/{id} — Removes slide from hero carousel.
  • GET /api/orders — Complete order ledger for Admin fulfillment.
  • POST /api/orders — Checkout order submission with line items.
  • PATCH /api/orders/{id}/status — Updates status (CONFIRMED/SHIPPED).
